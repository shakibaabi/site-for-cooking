# زعفرون | مواد از تو، غذا از ما

یک وب‌سایت کامل فارسی و راست‌به‌چپ برای پیشنهاد غذا بر اساس مواد موجود در خانه، با طراحی تیره و زعفرانی، رابط واکنش‌گرا و پنل مدیریت واقعی.

## امکانات تحویل‌شده

- **۲۴ دستور آماده** در پنج بخش: ۱۲ ایرانی، ۳ فرنگی، ۳ دسر، ۳ نوشیدنی و ۳ پیش‌غذا.
- **۶۸ ماده اولیه**؛ انتخاب هم‌زمان چند ماده، جست‌وجو و گروه‌بندی مواد.
- پیشنهاد مبتنی بر تطبیق واقعی مواد ضروری؛ نمایش مواد ضروری موجود، مواد کم‌دار و افزودنی‌های اختیاری.
- فیلتر «فقط با مواد موجود» و «حداکثر دو ماده کم‌دار»؛ تنظیم فرض موجود بودن نمک، روغن، فلفل و زردچوبه.
- جست‌وجوی فارسی با نرمال‌سازی ی/ي، ک/ك، فاصله و نیم‌فاصله؛ جست‌وجو در نام غذا، مواد و برچسب‌ها.
- منوی جداگانه و صفحه اختصاصی ایرانی، فرنگی، دسر، نوشیدنی و پیش‌غذا.
- فیلتر دسر/نوشیدنی سبک و بدون شکر افزوده، با توضیح تفاوت قند طبیعی و شکر افزوده.
- صفحه هر دستور: عکس، مقدار دقیق مواد، تغییر خودکار مقدارها با تعداد نفرات، مراحل پخت، آماده‌سازی، پخت، استراحت/سردشدن، سطح دشواری و نکته سرآشپز.
- حالت متمرکز آشپزی و علامت‌گذاری مراحل انجام‌شده.
- ذخیره دستورهای محبوب و لیست خرید در مرورگر؛ تیک خرید، کپی و دانلود لیست.
- پنل مدیریت با ورود: افزودن، ویرایش و حذف واقعی دستور، تغییر بخش و دسته‌بندی، برچسب، مواد ضروری/اختیاری، مرتب‌سازی مراحل، لینک منبع و آپلود تصویر.
- داده دستورها در سرور ذخیره می‌شود و پس از رفرش/راه‌اندازی مجدد باقی می‌ماند.
- تصاویر و فونت محلی؛ بدون وابستگی رابط به CDN.
- تست‌های واحد، تست مرورگر و راهنمای توسعه.

## اجرای سریع دمو

پیش‌نیاز: **Node.js 20 یا جدیدتر** و npm. نصب اولیه بسته‌ها به اینترنت نیاز دارد.

```bash
cd zaferoon
npm ci
npm run dev
```

در مرورگر باز کنید: **http://localhost:3000**

پنل مدیریت: **http://localhost:3000/admin**

حساب پیش‌فرض فقط برای دمو:

```text
Username: admin
Password: demo12345
```

برای اجرای سریع در ویندوز، `start-demo.bat` و در لینوکس/مک، `./start-demo.sh` هم آماده است. این فایل‌ها وابستگی‌های لازم را نصب و دموی buildشده را اجرا می‌کنند. سپس نشانی بالا را در مرورگر باز کنید.

برای امتحان کردن پیشنهاد غذا، «گوجه‌فرنگی» و «تخم‌مرغ» را انتخاب کنید و روی «پیشنهاد غذا» بزنید. با فعال بودن مواد پایه، املت گوجه باید آماده پخت باشد. مواد میوه‌ای هم دستورهای نوشیدنی را پیشنهاد می‌دهند.

**نکته:** این پروژه یک فایل HTML مستقل نیست؛ بخش مدیریت و پیشنهادها به API نیاز دارند. برای دموی کامل، دستور بالا را اجرا کنید. باز کردن مستقیم `index.html` از فایل‌سیستم کافی نیست.

## دموی بهینه با فایل‌های build

```bash
npm run build
npm run demo
```

این دستور همان API واقعی را با رابط buildشده و حساب دمو اجرا می‌کند. `--demo` صرفاً برای نمایش است؛ آن را روی اینترنت عمومی به‌عنوان production منتشر نکنید. فایل build نیز همراه آرشیو تحویل می‌شود.

## اجرای نسخه بهینه انتشار

فایل `.env.example` را در `.env` کپی و یک رمز قوی **حداقل ۱۲ نویسه** تعیین کنید:

```dotenv
PORT=3000
ADMIN_USERNAME=your-admin
ADMIN_PASSWORD=your-long-unique-password
```

سپس:

```bash
npm run build
npm start
```

سرور Express هم فایل‌های build و هم API را روی یک پورت ارائه می‌کند. نسخه production با رمز دمو یا رمز کوتاه شروع نمی‌شود. برای استفاده عمومی HTTPS و یک reverse proxy مناسب ضروری است.

### Docker

```bash
docker build -t zaferoon .
docker run --rm -p 3000:3000 \
  -e ADMIN_USERNAME=your-admin \
  -e ADMIN_PASSWORD=your-long-unique-password \
  -v zaferoon-data:/app/data \
  -v zaferoon-uploads:/app/public/images/uploads \
  zaferoon
```

اگر میزبان TLS را پایان می‌دهد، فقط در صورت شناخت دقیق پراکسی مورد اعتماد، `TRUST_PROXY=1` تنظیم شود. احراز هویت در این نسخه با توکن Bearer و `sessionStorage` است؛ متغیر `COOKIE_SECURE` لازم نیست.

## داده‌ها و پشتیبان‌گیری

- در اولین اجرا، `data/store.json` از `server/seed.js` و `server/seed-extra.js` ساخته می‌شود.
- ویرایش‌ها به‌صورت فایل موقت و rename اتمیک ذخیره می‌شوند.
- تصاویر آپلودی در `public/images/uploads/` قرار می‌گیرند.
- برای بکاپ، `data/store.json` و پوشه تصاویر آپلودی را نگه دارید.
- برای بازنشانی دمو، سرور را متوقف کنید، از داده‌ها بکاپ بگیرید و فقط `data/store.json` را حذف کنید؛ اجرای بعدی داده‌های اولیه را برمی‌گرداند.
- تغییر فایل seed، یک پایگاه داده از قبل ساخته‌شده را خودکار بازنویسی نمی‌کند؛ این رفتار برای حفظ ویرایش‌های مدیر عمدی است.
- موجودی خانه، علاقه‌مندی‌ها و لیست خرید در `localStorage` همان مرورگر ذخیره می‌شوند. این نسخه حساب کاربری عمومی و همگام‌سازی بین دستگاه‌ها ندارد.
- اگر مرورگر ذخیره‌سازی را مسدود کند، نشست همان صفحه با fallback حافظه‌ای کار می‌کند؛ پس از رفرش باید دوباره وارد شوید.
- نشست مدیر ۸ ساعت اعتبار دارد و با راه‌اندازی مجدد سرور پایان می‌یابد؛ رمز در حافظه به‌صورت هش bcrypt بررسی می‌شود.

## منطق پیشنهاد غذا

1. مواد ضروری و اختیاری هر دستور از هم جدا هستند.
2. آب همیشه موجود فرض می‌شود. با فعال بودن گزینه مواد پایه، روغن، نمک، فلفل و زردچوبه نیز موجود فرض می‌شوند؛ یخ جزو این فرض نیست.
3. دست‌کم یک ماده اصلی انتخاب‌شده باید با دستور تطبیق داشته باشد؛ انتخاب صرفاً آب یا نمک، همه غذاها را پیشنهاد نمی‌دهد.
4. درصد تطبیق از **مواد اصلی ضروری، بدون مواد پایه** محاسبه می‌شود.
5. ابتدا دستورهای بدون ماده ضروری کم‌دار، بعد درصد تطبیق بالاتر، تعداد تطبیق بیشتر و زمان کل کمتر نمایش داده می‌شوند.
6. در فیلتر «فقط با مواد موجود»، کمبود افزودنی‌های اختیاری، غذا را حذف نمی‌کند. جزئیات اختیاری در کارت و صفحه دستور دیده می‌شود.
7. زمان کل = آماده‌سازی + پخت + استراحت/سردشدن ثبت‌شده. خیساندن طولانی بعضی مواد ایرانی در متن مراحل جداگانه آمده است.

این پیشنهادها **تطبیق الگوریتمی** هستند، نه اتصال به مدل هوش مصنوعی یا توصیه تغذیه‌ای شخصی.

## ساختار پروژه

```text
zaferoon/
├── src/
│   ├── components/          # منو، انتخاب مواد، کارت، مودال، لیست خرید، ویرایشگر
│   ├── pages/               # خانه/بخش‌ها، دستور، ذخیره‌ها، مدیریت و 404
│   ├── lib/                 # نوع‌ها، API client، state و ابزارهای تطبیق
│   ├── styles.css           # طراحی و breakpointهای موبایل
│   └── main.tsx
├── server/
│   ├── index.js             # REST API، auth، upload و سرو فایل‌ها
│   ├── domain.js            # اعتبارسنجی و منطق پیشنهاد
│   ├── repository.js        # لایه ذخیره‌سازی قابل جایگزینی
│   ├── seed.js              # کاتالوگ و دستورهای ایرانی
│   ├── seed-extra.js        # دستورهای بخش‌های تازه با منابع
│   └── tests/
├── e2e/                    # تست‌های کاربری Playwright
├── public/
│   ├── images/
│   ├── fonts/               # Vazirmatn + مجوز OFL
│   └── favicon.svg
├── data/                    # پایگاه داده فایل‌محور در زمان اجرا
├── docs/ARCHITECTURE.md
├── SOURCES.md
├── Dockerfile
├── .env.example
├── package-lock.json
└── README.md
```

## تست

```bash
npm test              # تست واحد منطق، اعتبارسنجی و ماندگاری CRUD
npm run check         # بررسی TypeScript
npm run build         # build رابط
```

تست مرورگر، با سرور دمو در حال اجرا:

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

تست مرورگر یک دستور با پیشوند آزمایشی ایجاد و پس از بررسی حذف می‌کند. روی داده production اجرا نکنید. URL دمو و اعتبارنامه آزمایش را می‌توان با متغیرهای `E2E_BASE_URL`, `E2E_ADMIN_USERNAME`, `E2E_ADMIN_PASSWORD` تعیین کرد.

## توسعه بعدی

رابط React + TypeScript + Vite است و API با Express، Zod و bcryptjs ساخته شده. ذخیره‌سازی از routeها جداست؛ برای چند کاربر/چند پردازش، Repository فایل‌محور را با SQLite/PostgreSQL جایگزین کنید. مسیرهای پیشنهادی: حساب کاربر، امتیازدهی، برنامه هفتگی، فیلتر آلرژی، ارزش تغذیه‌ای معتبر و جست‌وجوی پیشرفته. راهنمای API و جزئیات در `docs/ARCHITECTURE.md` قرار دارند.

## نکات انتشار و حقوق محتوا

- این نسخه برای دمو و شروع توسعه آماده است، نه سرویس پرترافیک چندسروره. نشست‌ها و rate limit حافظه‌ای هستند و ذخیره‌سازی JSON تک‌پردازشی است.
- پیش از انتشار، رمز مدیر را تغییر بدهید، HTTPS و بکاپ را فعال کنید و پایش خطا اضافه کنید.
- چهار عکس مرجع اینترنتی صرفاً در دمو آمده‌اند؛ پیش از استفاده تجاری برای آن‌ها مجوز بگیرید یا جایگزین کنید. ۲۰ عکس دیگر اختصاصی و AI-generated هستند. جزئیات منابع و حقوق در **SOURCES.md**.
- دستورها، زمان‌ها و تصاویر نمایشی‌اند؛ تصاویر نتیجه دقیق پخت را تضمین نمی‌کنند. «بدون شکر افزوده» به معنی بدون قند نیست و اطلاعات پزشکی/تغذیه‌ای شخصی ارائه نمی‌شود.
